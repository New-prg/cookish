# Сервер — основная копия, телефон — кэш

Статус: принято 2026-10-11, эпик #66. Заменяет
[ADR-0001](0001-offline-first-with-account-sync.md).

Основная копия данных Cookish живёт на сервере, в полном Ядре. На телефоне
работают Кэш и Outbox: Кэш держит окна данных для скорости и работы без сети,
Outbox отправляет правки командами. Сервисы (Ассистент, Заполнитель, решения по
Тычкам, поиск в Open Food Facts и USDA, позже аккаунт и биллинг) работают на
сервере. Так Cookish получает несколько устройств и восстановление после потери
телефона без выбора, чья копия главнее, а ключ провайдера ИИ уходит с телефона.

## Решения

- **Гостевой аккаунт.** Регистрации нет: при первом запуске приложение
  незаметно создаёт Гостевой аккаунт, почту можно привязать потом. Без сети
  гостевой идентификатор создаётся на телефоне, а на сервере гость
  регистрируется при первом выходе в сеть. Приложение стартует и без сети.
- **Без сети работает всё, кроме ИИ:** Учёт, Покупки, правки плана, Продукты.
  Правка сразу видна в Кэше и встаёт командой в Outbox. Outbox досылает команды
  полному Ядру; у каждой команды свой id, поэтому повторная доставка ничего не
  дублирует.
- **При конфликте побеждает сервер.** Полное Ядро переигрывает команду на
  основной копии. Если команда больше не применима, Кэш её откатывает, а
  человек видит, что не применилось и почему.
- **Окна Кэша** — константы в коде:
  - План и Учёт питания и спорта: от −14 до +14 дней;
  - все свои Продукты;
  - открытые Запросы и последние 30 закрытых;
  - Профиль и настройки;
  - заголовки Закладок, сам тред грузится при открытии;
  - последние 20 Наборов изменений.

  Остальное подгружается по запросу и без сети недоступно.
- **ИИ только через сервер и аккаунт.** Агент живёт в Сервисах. Данные он
  читает через порт данных и возвращает только сериализуемые результаты:
  спецификации Предложений, обновления Продуктов, вопросы Заполнителя. Применяет
  их Ядро своими командами: заново проверяет на текущем плане и пишет Набор
  изменений.
- **Временное исключение для теста ИИ.** Пока сервера нет, ключ провайдера
  вводится во временном поле Профиля, хранится только на телефоне и передаётся
  Сервисам в том же процессе. Исключение снимается, когда Сервисы ИИ переезжают
  на сервер (#31).
- **Границы слоёв.** Между UI и Ядром граница синхронная: снимок и команды.
  Между UI и Сервисами граница асинхронная: всё, что её пересекает,
  сериализуется. Пока сервера нет, полное Ядро над `localStorage` и Сервисы
  работают в том же процессе за локальным транспортом, который пропускает
  каждое сообщение через `structuredClone`. Переезд на сервер меняет транспорт и
  хранилище полного Ядра, а не архитектуру.

## Раскладка кода

| Слой | Папка | Где работает |
|---|---|---|
| UI | `mobile-shell/ui/` | телефон |
| Ядро | `mobile-shell/core/` | полное Ядро — сервер; Кэш и Outbox — телефон |
| Сервисы | `mobile-shell/services/` | сервер |
| Транспорт | `mobile-shell/transport/` | сейчас локальный, потом HTTP |

`core/` и `services/` не импортируют ничего браузерного: `ui/`, `window`,
`document`, `localStorage`, Capacitor. Хранилище и сеть приходят адаптерами.

## Последствия

- Правка без сети может не примениться. Человек узнает об этом после выхода в
  сеть. По ADR-0001 побеждала локальная копия, теперь сервер может отклонить
  локальную правку.
- Кэш с окнами и Outbox сложнее одного локального пакета.
- Существующий пакет `cookish.android.data.v1` становится данными полного Ядра,
  Кэш строится из него, ничего не теряется (#70). При первом подключении к
  серверу эти данные загружаются в Гостевой аккаунт (#30).
