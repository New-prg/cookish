Job to be done

Cookish помогает небольшой семье (1–2 человека) планировать еду, превращать план в общий список покупок, фиксировать траты и вести персональный рацион — без своего backend: телефон = source of record, Google Sheets = shared sync fabric.

Bottom navigation (required)
Tab Purpose Primary actions
Сводка Home health: open lists, spend, shortcuts Create request; open products
Запросы All shopping notes Create; open note
Рацион Personal meal calendar Period nav; select; request; delete
Профиль Account, sheet, permissions Google/sheet; products; clear data
IA rules
  • One primary surface per job. Buying on the request note, not a parallel wizard.
  • Create = open empty artifact. No “confirm create” form for requests.
  • Destructive / system settings live in Profile, not on home.
  • Fixed chrome: top bar + bottom nav outside scrollport; only main scrolls.
  • Commit on leave: blur / Enter / Готово — not every keystroke.
03 · Personas & primary scenarios
A · Planner

Often at home

B · Buyer

Often in store

Opens shared request, checks off bought items, sometimes replaces via barcode, enters price occasionally.

C · Shared household

Same spreadsheet

Both may edit offline; notifications when the other creates a request.

05 · What already works well
Strengths
# Strength Why it matters
1 Keep-like requests Empty note, trailing blank line, Enter → next, checkbox = bought
2 One job per surface Purchase on the note, not a separate wizard
3 Offline-first + sync chip Does not lock UI on every save
4 Input protection Commit on blur/Enter; sync does not steal focus while editing
5 Ration → Request Meaningful end-to-end differentiator path
6 Product PRD docs/PRODUCT_REQUIREMENTS.md — rare maturity for this size
Must-not-regress behaviors

Request opens as Keep-style list · product name not on every keystroke · line unit is request-local · checkbox buy (one request = one receipt) · Готово commits without “unsaved” confirm · bottom nav pinned · ration selection toolbar stable · ration Удалить works on selection.

06 · UX improvement backlog
P0 — Correctness & “alive” feel HIGH
Issue Why it hurts Proposal
Full innerHTML re-render after check / ration edit Keyboard, focus, jank — breaks note-feel Partial DOM update of one row; virtual list later
Dual write path JS + Java worker Ghost overwrite under concurrent multi-user edits One canonical merge; non-wipe Sheets write
History / rollback local-only Partner does not understand “I rolled back” Badge «только на этом устройстве» + roadmap sync history
P1 — IA clarity & discovery MEDIUM
Issue Proposal
Products buried under Summary / Profile 5th tab or sticky entry + contextual FAB
Summary ≈ Profile metrics duplicate Summary = action queue: buy today, sync error, ration without products
Ration → request not obvious Onboarding tip / empty-state: «Выделите дни → Запросить»
Unicode tab icons (⌂ ≡ ▦ ○) SVG icon set + active color; Cookish brand on splash
request-answer vs checkbox flow Hide advanced path; primary = ✓ on line
P2 — In-store friction MEDIUM
Concrete moves
  • «Режим магазина» — larger targets, hide history/delete, keep screen on
  • Deep link from notification → request-edit
  • Pull-to-refresh language on lists
  • Price: quick preset / optional end-of-receipt total
  • Filter «осталось купить»; haptic on check
Buyer success metric

Time from notification tap → first checkbox under 3 seconds. Zero navigation hops when there is a single active open request.
