# Cookish

Учёт продуктов, запросов на закупку, рациона и фактических трат.

Android-приложение автономно. Интерфейс и данные живут на телефоне. Без
аккаунта доступны локальные функции, Cookish сразу открывает главный экран;
сетевые функции (синхронизация и ИИ) выключены до входа. Схема offline-first
с аккаунтом описана в
[`docs/adr/0001-offline-first-with-account-sync.md`](docs/adr/0001-offline-first-with-account-sync.md).

Термины Продукт, Запрос, Покупка, Рацион, Цикл рациона, История питания и
локальные данные описаны в [`CONTEXT.md`](CONTEXT.md). Поведение экранов — в
[`docs/PRODUCT_REQUIREMENTS.md`](docs/PRODUCT_REQUIREMENTS.md).
Отчёты от 7 августа 2026 года лежат в [`reports/archive/`](reports/archive/)
и описывают прежний курс, не текущий продукт.

## Данные

Cookish хранит Продукты, Запросы, Покупки, Рацион и Историю питания только на
устройстве, в локальном пакете `cookish.android.data.v1`. Это и есть текущее
хранилище.

Нет обязательного Google-входа. Google Таблицы не являются хранилищем и не
нужны для работы. Существующие локальные данные после обновления приложения
продолжают открываться. Синхронизация между телефонами появится только после
входа в аккаунт; без него правки никуда не уезжают.

Сборка:

```powershell
npm install
npm run android:apk
```

Готовый файл: `output/Cookish-debug.apk`.

## Выпуск Android-релиза

Релизы публикуются из ветки `master` скриптом `scripts/release-android.ps1`.
Он запускает GitHub Actions: тесты, подписанный APK, тег `vX.Y.Z` и GitHub
Release с файлами `Cookish.apk`, `Cookish.apk.sha256` и `update.json`.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/release-android.ps1 -DryRun
powershell -ExecutionPolicy Bypass -File scripts/release-android.ps1
```

Без `-Version` скрипт берёт следующий patch от последнего релиза. Без `-Notes`
собирает описание из коммитов с прошлого релиза.

Приложение при запуске смотрит последний публичный GitHub Release. Если там
есть более новая версия и файл `Cookish.apk`, в профиле появляется кнопка
**Обновить**. APK скачивается в закрытый кэш приложения, проверяется по SHA-256,
после чего Android показывает системное подтверждение установки. При первом
обновлении Android также попросит разрешить установку из Cookish.

Release APK всегда должен быть подписан одним и тем же ключом. Ключ хранится в
GitHub Secrets (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
`ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`), а его резервная копия — вне
репозитория. Debug-сборка подписана другим ключом, поэтому перед первой установкой
официального release APK ранее установленную debug-сборку нужно удалить один раз.

Запуск одной командой (телефон **или** эмулятор):

```powershell
.\run.cmd
# или (обход ExecutionPolicy):
powershell -ExecutionPolicy Bypass -File .\run.ps1
# или:
npm run
# только USB-телефон:
npm run run:phone
```

Если `.\run.ps1` пишет *running scripts is disabled* — это политика PowerShell.
Используйте `.\run.cmd`, `npm run` или `Bypass` как выше (не нужно менять политику системы).

Что делает скрипт автоматически:

1. Берёт **JBR/SDK Android Studio**
2. При необходимости ставит **npm-зависимости**, **cmdline-tools**, SDK-пакеты
   (`platform-tools`, `emulator`, `platforms;android-36`, `build-tools`, system image)
3. Принимает SDK licenses
4. Создаёт AVD **Cookish_Pixel** (Pixel 6 + Google Play image), если нет устройств
5. Запускает эмулятор, ждёт boot, настраивает (клавиатура, GPU, без анимаций)
6. `cap sync` → `gradlew installDebug` → старт Cookish

Сборка через junction `%USERPROFILE%\cookish-build` (ASCII-путь для Gradle/Studio).

| Команда | Действие |
|---------|----------|
| `.\run.cmd` / `npm run` | Полный цикл: **USB-телефон если есть, иначе эмулятор** |
| `.\run.cmd -Usb` | То же явно (USB → fallback на эмулятор) |
| `.\run.cmd -Emulator` | Всегда эмулятор |
| `.\run.cmd -PhysicalOnly` / `npm run run:phone` | Только USB-телефон |
| `.\run.cmd -Avd NAME` | Свой AVD |
| `.\run.cmd -SkipDeps` | Не качать npm/SDK |
| `.\run.cmd -SkipBuild` | Только install/launch |
| `.\run.cmd -SkipTests` | Без unit-тестов |
| `.\run.cmd -Serial ID` | Конкретное устройство |
| `.\run.cmd -OpenStudio` | Открыть модуль в Android Studio |

Запрос создаётся сразу как пустая заметка: в строке вводится только название
товара, количество задаётся компактным шагом, единица берётся из карточки
продукта. Сохранённый товар становится чипом (тап — карточка). Галочка отмечает
покупку; свайп или долгий тап открывает цену, фактическое количество и штрихкод.
Один продукт может присутствовать в запросе только один раз. Неподтверждённый
товар можно обогатить сканом; подтверждённый при замене сохраняется, а купленный
SKU пишется отдельно.

Рацион открывается экраном «Сегодня»: приёмы пищи по времени, порции, КБЖУ и
состояние каждого приёма. Новый приём начинается как «не отмечено»; короткая
кнопка отмечает «съедено», остальные действия живут в карточке приёма. Будущие
дни показываются в оверлее Плана: там выбирают дату, создают или меняют Особый
день и превращают выбранный диапазон в Запрос с округлением до упаковок.
Прошлые дни и исправления живут в оверлее Истории. Цикл рациона и Версии
остаются внутренним расчётом и в интерфейсе не показываются. Календарный
редактор с режимами день, неделя и месяц, шаблоны дней и режим выделения
убраны: их содержимое переезжает в план и Историю питания при миграции.

### Правила локальных данных

Перед сохранением приложение нормализует пакет:

1. Продукты и запросы дедуплицируются по `id`.
2. Позиции запроса дедуплицируются по `productId`.
3. У запроса один чек покупок; позиции чека дедуплицируются по `productId`.
4. Повторная запись в тот же чек обновляет его. Отдельный чек на тот же запрос
   не создаётся.
5. Каталог продуктов не хранит складской остаток: количества существуют только
   в запросах и покупках, а цены покупок используются для статистики расходов.
6. Рацион хранится как план (Версии рациона и Особые дни) и История питания.
   Существующие дни и шаблоны из прежних версий приложения мигрируют в эту
   схему без потерь. При конфликте записей побеждает более поздний
   `updatedAt`.

Запрос остаётся активным после частичной покупки и закрывается только тогда,
когда суммарно куплено всё запрошенное количество по каждой позиции. Создание,
редактирование запроса и изменение покупки сохраняются в журнале версий на
устройстве. Из карточки запроса можно откатить позиции, покупки и статус к любой
сохранённой версии; сам откат становится новой записью истории.

### Обработанные пограничные случаи

- Повторная запись той же покупки безопасна: второй чек и вторая строка в
  статистике не появляются.
- Редактирование покупки заменяет её прежнюю версию.
- Товар с ненулевым количеством или ценой в покупке нельзя удалить из запроса.
- Редактирование старого запроса не создаёт повторные покупки в статистике.
- Покупка с нулевым количеством сохраняется; пустая цена считается нулевой.
