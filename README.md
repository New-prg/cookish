# Cookish

Учёт продуктов, запросов на закупку, рациона и фактических трат.

Android-приложение автономно: интерфейс и данные находятся на телефоне.
Подключённая Google Таблица обновляется после изменений и фоновой задачей
WorkManager каждые 15 минут при наличии сети. Фоновая синхронизация включает
листы **Продукты**, **Запросы**, **Покупки** и **Рацион** (если лист рациона
уже создан приложением).

При первом запуске приложение проводит настройку: запрашивает разрешение на
уведомления и исключение Cookish из оптимизации батареи (можно пропустить и
включить позже в профиле), затем предлагает войти в Google и создать либо
подключить таблицу синхронизации. До входа и выбора таблицы основной экран
не открывается.

Сборка:

```powershell
npm install
npm run android:apk
```

Готовый файл: `output/Cookish-debug.apk`.

## Выпуск Android-релиза

Релизы собираются вручную из ветки `master` в GitHub Actions. Workflow запускает
тесты, собирает подписанный APK, создаёт тег `vX.Y.Z` и публикует GitHub Release
с файлами `Cookish.apk`, `Cookish.apk.sha256` и `update.json`.

1. Откройте **Actions → Release Android → Run workflow**.
2. Оставьте ветку `master`.
3. Укажите новую версию строго в формате `MAJOR.MINOR.PATCH`, например `5.4.0`.
4. При желании добавьте описание изменений и запустите workflow.

Прямая ссылка на запуск:
<https://github.com/New-prg/cookish/actions/workflows/release-android.yml>

Приложение проверяет последний публичный GitHub Release при запуске. Если в нём
есть более новая версия и файл `Cookish.apk`, в профиле появляется кнопка
**Обновить**. APK скачивается в закрытый кэш приложения, проверяется по SHA-256,
после чего Android показывает системное подтверждение установки. При первом
обновлении Android также попросит разрешить установку из Cookish.

Release APK всегда должен быть подписан одним и тем же ключом. Ключ хранится в
GitHub Secrets (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
`ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`), а его резервная копия — вне
репозитория. Debug-сборка подписана другим ключом, поэтому перед первой установкой
официального release APK ранее установленную debug-сборку нужно удалить один раз.

Запуск одной командой (телефон **или** эмулятор):

```powershell
.\run.cmd
# или (обход ExecutionPolicy):
powershell -ExecutionPolicy Bypass -File .\run.ps1
# или:
npm run
# только USB-телефон:
npm run run:phone
```

Если `.\run.ps1` пишет *running scripts is disabled* — это политика PowerShell.
Используйте `.\run.cmd`, `npm run` или `Bypass` как выше (не нужно менять политику системы).

Что делает скрипт автоматически:

1. Берёт **JBR/SDK Android Studio**
2. При необходимости ставит **npm-зависимости**, **cmdline-tools**, SDK-пакеты
   (`platform-tools`, `emulator`, `platforms;android-36`, `build-tools`, system image)
3. Принимает SDK licenses
4. Создаёт AVD **Cookish_Pixel** (Pixel 6 + Google Play image), если нет устройств
5. Запускает эмулятор, ждёт boot, настраивает (клавиатура, GPU, без анимаций)
6. `cap sync` → `gradlew installDebug` → старт Cookish  

Сборка через junction `%USERPROFILE%\cookish-build` (ASCII-путь для Gradle/Studio).

| Команда | Действие |
|---------|----------|
| `.\run.cmd` / `npm run` | Полный цикл: **USB-телефон если есть, иначе эмулятор** |
| `.\run.cmd -Usb` | То же явно (USB → fallback на эмулятор) |
| `.\run.cmd -Emulator` | Всегда эмулятор |
| `.\run.cmd -PhysicalOnly` / `npm run run:phone` | Только USB-телефон |
| `.\run.cmd -Avd NAME` | Свой AVD |
| `.\run.cmd -SkipDeps` | Не качать npm/SDK |
| `.\run.cmd -SkipBuild` | Только install/launch |
| `.\run.cmd -SkipTests` | Без unit-тестов |
| `.\run.cmd -Serial ID` | Конкретное устройство |
| `.\run.cmd -OpenStudio` | Открыть модуль в Android Studio |

Для Google-входа и Google Sheets в Google Cloud должны быть:

1. Включён Google Sheets API.
2. Создан OAuth-клиент типа Android.
3. Package name: `ru.listok.purchases` (технический id OAuth-клиента; имя
   приложения — Cookish).
4. SHA-1 debug-сертификата:
   `90:4F:BD:1C:8B:33:D5:7E:96:82:CD:26:F9:48:06:F9:D5:3A:39:9E`.
5. На экране согласия добавлены scopes:
   `openid`, `userinfo.email`, `userinfo.profile`, `spreadsheets`.
6. Android OAuth client id и project id лежат в
   `android/app/src/main/res/values/google_oauth.xml`.

Client Secret для Android-приложения не используется.

В профиле можно создать или подключить таблицу, открыть её для редактирования
в Google Sheets и отправить ссылку через системное меню Android.

Для совместной работы оба пользователя подключают одну и ту же Google Таблицу.
Приложение объединяет записи по идентификатору и времени изменения. Новые
активные запросы другого пользователя показываются системным уведомлением
после фоновой проверки. На Android 13+ необходимо разрешить уведомления.
Пока приложение открыто, общая таблица синхронизируется примерно каждые
30 секунд; во время редактирования интерфейс не перерисовывается принудительно.
После сворачивания используется фоновая проверка.

Запрос создаётся сразу как пустая «заметка» (в духе Google Keep): в строке
вводится только название товара, количество задаётся компактным шагом, единица
берётся из карточки продукта. Сохранённый товар становится чипом (тап — карточка).
Галочка отмечает покупку; свайп или долгий тап открывает цену, фактическое
количество и штрихкод. Один продукт может присутствовать в запросе только один раз.
Неподтверждённый товар можно обогатить сканом; подтверждённый при замене
сохраняется, а купленный SKU пишется отдельно.

### Схема синхронизации

Версию 5.3 необходимо установить на все устройства, подключённые к общей
таблице, до продолжения работы. Версии 4.x используют старую структуру листов и
версии 5.0 не передают транзакционные откаты ответов, поэтому не должны
синхронизироваться с таблицей после её перевода на новую схему.

Перед отправкой приложение формирует нормализованный пакет:

1. Продукты и запросы дедуплицируются по `id`.
2. Позиции запроса дедуплицируются по `productId`.
3. Каждый ответ имеет отдельный `response_id`; его позиции дедуплицируются по
   `productId`.
4. Повторная отправка того же `response_id` обновляет ответ по времени
   изменения. Другой `response_id` сохраняется как дополнительный ответ.
5. Каталог продуктов не хранит складской остаток: количества существуют только
   в запросах и покупках, а цены покупок используются для статистики расходов.
6. Рацион хранится по дням и владельцу (`owner|date`); при конфликте побеждает
   более поздний `updatedAt`.

Запрос остаётся активным после частичного ответа и закрывается только тогда,
когда суммарно куплено всё запрошенное количество по каждой позиции. Создание,
редактирование запроса и добавление или изменение ответа сохраняются в
**локальном** журнале версий на устройстве. Из карточки запроса можно откатить
позиции, ответы и статус к любой сохранённой версии; сам откат становится новой
записью истории. История версий **не синхронизируется** через Google Таблицу.

Старые строки листа «Покупки» автоматически преобразуются в один совместимый
ответ на запрос. Старые столбцы остатков в листах «Продукты» и «Запросы» читаются
только для совместимости, их значения игнорируются и удаляются при следующей
синхронизации. При одновременном редактировании одного объекта на двух
устройствах используется последняя версия по времени изменения; разные ответы
объединяются и не перезаписывают друг друга.

### Обработанные пограничные случаи

- Повторная отправка одного ответа безопасна: одинаковый `response_id` не
  создаёт вторую покупку в статистике.
- Два ответа на один запрос сохраняются отдельно, их количества и цены
  суммируются.
- Редактирование ответа заменяет только его прежнюю версию; остальные ответы
  не изменяются.
- Новый дополнительный ответ открывается с нулевыми количествами, чтобы
  случайно не повторить предыдущую закупку.
- Товар с ненулевым количеством или ценой в ответе нельзя удалить из запроса.
- Редактирование старого запроса не создаёт повторные покупки в статистике.
- Ответ с нулевым количеством сохраняется; пустая цена считается нулевой.
- После работы без сети разные ответы объединяются при следующей синхронизации.
  При конфликте правок одного и того же ответа побеждает версия с более поздним
  временем изменения.
